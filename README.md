# 论文写作 SOP · 中英双语两条产线

> 作者：红湖先生（GitHub @7xiaohui）

> 这不是「让 AI 帮你写论文」，而是把「从有个方向，到返修回来」拆成**可执行、可验收、可复用**的流程。
> 两条产线：**中文期刊论文**（8 份 SOP ＋ 总纲 ＋ 23 份提示词）、**英文 SSCI 投稿**（9 步 ＋ 5 个检查脚本）。

---

## 为什么会有这个仓库

写论文真正拖垮进度的，通常不是「不会写」，而是四件事：

1. **不知道下一步做什么**——流程只有步骤，没有判据；
2. **做完了不知道算不算做完**——没有验收标准，只能靠感觉；
3. **同一个坑反复踩**——失败没有沉淀，换个题目再踩一遍；
4. **AI 一介入就失控**——编数据、跑题、留痕，返工成本比手写还高。

这份仓库是上面四件事的产物：把流程写成文件，把能机械检查的写成脚本，把踩过的坑写成失败模式库。它来自真实的写作过程，按「哪里反复出错就补哪一条」迭代，不是先设计一套完美体系再倒推。

**它已经跑过真实论文，也保留了可复跑的验证方式**（见下文「验证」一节）。

## 两条产线

| | **中文线** [`zh/`](zh/) | **英文线** [`en/`](en/) |
|---|---|---|
| 适用 | 非实证中文期刊论文：政策对策、描述分析、理论构建 | 中文母语者的英文投稿：概念型、比较型、对策型、小调查 |
| 主线 | 8 份可单独执行的 SOP ＋ 总纲 | 9 步主流程 ＋ 5 份执行手册（skills） |
| 配套 | 23 份提示词、4 张模板、1 个核对脚本 | 7 张模板、5 个检查脚本、投稿件生成器、正负样本 |
| 入口 | [`zh/README.md`](zh/README.md) | [`en/README.md`](en/README.md) |
| 适合谁 | 中文写作、需要逐环节验收 | 中文定稿后要出英文、要投 SSCI |

两条线不是同一套东西的翻译，而是**两种不同的失败结构**：

- 中文线的敌人是**型错**（描述段写成论证段、论证段写成资料堆）与**编造**（数据、条款、文献）；
- 英文线的敌人是**学科归属**（写到一半发现这本刊不收）、**结构漂移**（越写越大、删不掉）与**语言拖累**。

所以两条线各自有独立的判据、模板和脚本；共用的是下面几条设计原则。

---

## 五条共用原则

1. **判据优先。** 每一步都写清「产出什么、什么样算过」。判据不过，不进入下一步——返回去补，比写完再发现便宜。
2. **脚本优先于模型。** 词数、标号映射、数字比对、文档属性、标点字形，这些能数出来的，先交脚本；模型只负责判断「这个差异要不要改」。
3. **复核必须独立。** 写的人不校自己的人。换模型、换会话，或把材料无状态重投一次。
4. **标记即欠账。** 【待核】【待定】【料N】在过程里有价值，在投稿稿里是事故。它们必须被清到零，且脚本零命中才算完。
5. **完成优先于完美。** 先跑通一条能用的流程，再迭代；不要为了体系漂亮而无限打磨。

完整说明见 [`docs/共享原则.md`](docs/共享原则.md)。

## 快速开始

### 中文线（5 分钟）

1. 打开 [`zh/0-总体SOP.md`](zh/0-总体SOP.md)，看「八份 SOP 一览」和「单独执行与跳跃执行」；
2. 只解决一个问题时，直接取对应那一份，不必跑全流程；
3. 需要提示词时，去 [`zh/提示词/`](zh/提示词/) 取，替换方括号里的占位信息即可；
4. 有稿子了，先跑核对脚本：

```bash
cd zh
python 工具/核对脚本.py refs 正文.md 参考文献.txt
```

### 英文线（5 分钟）

1. 打开 [`en/00-总览.md`](en/00-总览.md)，看九步全图；
2. 按「你现在的状态」表，从对应那一步进入；
3. 把稿子放进 `en/工具/input/`，双击 `run_all.bat`（Windows），或直接跑脚本：

```bash
python en/工具/scripts/check_counts.py en/工具/input en/工具/output
```

> 脚本只依赖 Python 标准库；`build_docx.py` 另需 `python-docx`。

## 验证：它到底能不能用

这个仓库不靠「我觉得挺好」来证明自己，而是留了可复跑的证据。

```bash
python tests/verify.py
```

`verify.py` 会做两件事：

1. 把 `en/工具/samples/good.md` 和 `bad.md` 分别喂给 5 个检查脚本，断言 **good 全过、bad 至少 5 项失败**；
2. 用中文线的固定样本，断言 `refs` / `marks` / `punct` 在干净样本上零命中、在脏样本上能报出问题。

预期输出结尾为：

```
==== 全部通过：英文线 10/10，中文线 6/6 ====
```

> Windows 用户也可以直接双击仓库根目录的 `run_checks.bat`：它会依次跑验证和隐私扫描，并停住窗口，不会一闪而过。

另有一个隐私守门脚本，扫描邮箱、手机号、身份证号、ORCID；GitHub Actions 在每次提交时同时跑这两项：

```bash
python tests/scan_private.py
```

英文线的真实记录（不是样本，是一篇 7,441 词 / 75 条文献的英文稿）：五个脚本依次抓出了摘要与正文发现项数不一致、正文引了但文献表没有的条目、17 条未引用文献、14 条缺 DOI、1 处人称混用等。**脚本会误报，也会漏报**——它的定位是缩小人工核对范围，不是替代人。

## 它不做什么

- **不保证录用。** 决定录用的是选题与证据，不是流程；
- **不替你产生观点。** 流程能防止跑偏，不能代替判断；
- **不保证母语级英文。** 英文线能保证术语一致、语法正确、语域规范；要再进一步，只有付费母语润色；
- **不适合需要统计推断的实证论文。** 中文线明确按非实证论文设计；实证论文可沿用部分环节，但核验环节需替换；
- **不是代写工具。** 见下节。

## 使用边界与学术诚信

这份仓库公开的目的，是让「怎么做才不出错」这件事可以被检查和讨论，**不是提供一条规避学术规范的捷径**。

- 使用 AI 的范围与方式，**按目标期刊、学校或机构的要求如实声明**；各刊政策不同，英文线第 3 步专门要求先读《作者指南》的 AI 政策；
- **不得伪造**数据、文献、条款、访谈记录。两条线的核对脚本与失败模式库，主要就是拦这一类错误；
- 中文线里「降 AI 率改写」一节，目的是让表述更接近作者本人的写作，**不是伪造「从未使用 AI」**；若机构要求申报，按实际申报；
- 引用他人观点必须标注；已发表内容只可「引用 ＋ 概括」，不可整段翻译后另投。

完整说明见 [`docs/使用边界.md`](docs/使用边界.md)。

## English summary

Two field-tested, checkable workflows for academic writing, built for a Chinese-first author:

- **`zh/`** — eight SOPs for non-empirical Chinese journal papers: topic screening, literature and fact registers, type-aware drafting, citation and trace verification, submission packaging. 23 copy-paste prompts, 4 templates, 1 verification script.
- **`en/`** — a 9-step pipeline for English SSCI submissions: venue fit, literature triage, argument-first drafting, translation checks, anonymised submission files. 5 checkers with positive/negative samples, a docx builder.

Design stance: every step has an explicit pass criterion; anything countable is checked by script, not by eye; the reviewer never shares context with the writer. The docs are CC BY-NC-SA 4.0 (non-commercial, share-alike), the code is MIT. Run `python tests/verify.py` to reproduce the sample checks.
