# 共享原则

> 两条产线各自有成套的 SOP，但真正决定「会不会脱轨」的是下面几条。它们是跨领域、跨语言通用的；换成工伤知识库、换成课程讲义，同样适用。

---

## 一、判据优先：每一步都要能回答「算不算过」

大多数写作建议给的是动作（「多读文献」「先写提纲」），不是判据。动作无法验收，所以做完也不知道对不对。

本仓库每个动作后面都跟一条判据：

| 动作 | 判据（示例） |
|---|---|
| 定选题 | 一句话说清「改变谁的什么判断」；说不出 = 还没定 |
| 读文献 | 六组中每组 ≥2 篇，且能写出「他们说 / 分歧 / 我站哪」三句 |
| 定结构 | 只读每段第一句，能复述完整论证 |
| 写初稿 | 每段 4–6 句、120–180 词，主张与证据一一对应 |
| 译英文 | 术语零禁用、回译零漂移、数字零差异 |
| 做投稿件 | 匿名稿身份信息 0 处，且附录/参考文献/图表未被误删 |

**判据不过怎么办**：停，回到上一步补，不要带着问题往下走。流程的价值不在「走完」，在「每一步都可回退」。

---

## 二、脚本优先于模型：能数出来的，不交给人眼

有四类错误容易被肉眼放过，也容易被模型「顺手圆过去」：

1. **数量类**：词数、摘要长度、关键词个数、发现项数；
2. **映射类**：正文引用 ↔ 文献表、论点 ↔ 文献 ↔ 章节、数字 ↔ 底表；
3. **残留类**：过程标记、占位符、版本尾注、文档属性、修订痕迹；
4. **字形类**：ASCII 引号、中文标点的字体归属（`w:hint="eastAsia"`）、引号开合。

这些一律先跑脚本：

```bash
# 英文线
python en/工具/scripts/check_counts.py en/工具/input en/工具/output

# 中文线
python zh/工具/核对脚本.py refs 正文.md 参考文献.txt
```

**模型负责判断，脚本负责「有没有」。** 脚本说「这里有」，人再判断「要不要改」；脚本没报，不等于没问题——它只覆盖能被规则描述的部分。

---

## 三、复核必须独立：写的人不校自己的人

同一个上下文里做复核，等于让自己给自己判卷：前面写错的假设，后面会当成前提继续用。

所以两条线都规定：**复核者不得与写作者共享上下文**。实现方式任选：

- 换一个模型；
- 换一个会话，只投喂「产物 ＋ 判据」，不投喂写作过程；
- 把材料无状态重投一次（不带此前的对话）。

英文线把这套做法落在 skills/ 的五个执行手册里；中文线把它写成「4-2 / 5-2 / 6-3 / 7-4 的复核者不得与写作者共享上下文」。

---

## 四、标记即欠账：过程标记必须清零

写作过程中需要临时标记，否则 AI 会替你编：

- 【待核】= 信息不足，禁止编造；
- 【待定】= 分类待人工确认；
- 【待补出处】= 正文必需但来源待补；
- 【料N】= 事实材料编号；
- 【论N】= 论点编号。

它们在写作期是护栏，在投稿稿里是事故。**清理不是「删掉标记」，是「补上内容」**：补不上的，要么降级表述，要么删掉这句。

判据：脚本零命中 + 人工逐条确认删留。

---

## 五、完成优先于完美：先跑通，再迭代

这套东西最容易掉进的坑，是把它做成一个漂亮的体系，然后一篇论文也没写完。

所以有两条硬纪律：

1. **先做最小闭环**：选题 → 结构 → 一节正文 → 一次检查，跑通再扩展；
2. **先删后加**：改流程时，先删一条旧的，再加一条新的。只加不删，半年后又回到几万字。

英文线 README 里的「三条使用纪律」和中文线的「轻量路径」，都是这条原则的具体化。

---

## 六、诚实定位：写清「不解决什么」

每份文档开头都标了「不解决什么」：

- 英文线不保证录用、不保证母语级自然；
- 中文线不做统计推断、不替代导师与审稿人；
- 两条线都不替你产生观点。

把边界写清楚，不是为了免责，是为了**防止把方法当护身符**：方法只能降低低级错误，不能提高选题价值。
