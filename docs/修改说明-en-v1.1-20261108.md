# 英文线 v1.1 修改说明（2026-11-08）

> 范围：`en/` 全线。`zh/`（中文期刊线）不动——它是另一条产线，不是这套九步的翻译。
> 原则：只补"可执行判据"，不加步骤、不写理由进正文；理由集中在本文件。
> 触发：一篇真实论文从 IJCP 桌拒转到 JTCC 投稿的全过程。

---

## 一、为什么要改（四个真实故障）

| # | 故障 | 证据 |
|---|---|---|
| 1 | 换刊后字数口径突变，一次砍 45% | IJCP 8,000（不含文献）→ JTCC 7,000（含表/文献/图注/注）；原稿 12,364 词，压到 6,312 |
| 2 | 正文称 "coded all content"，实际抖音 47 条只有账号级汇总 | 合并编码表明确写"论文仅引用其汇总统计，不引用逐条字段" |
| 3 | 核心概念定义大于证据 | `platform-mediated authorisation` 定义说"定义权再分配"，数据只支持"可见权转移" |
| 4 | 系统 100 字符按 100 词写 | 推广字段 716/100 字符被拒 |

这四类都不是"写作水平"问题，是"判据缺一项、AI 就会顺着写"的问题。所以只补判据，不补道理。

## 二、逐文件改了什么、为什么

### `01-主流程.md`

| 改动 | 为什么 |
|---|---|
| 3-1 加"收录集一步到位" | 有 IF ≠ SSCI；ESCI 也有 IF 和分区。只认 MJL 的 Collection 字段，防 JHT 式误判 |
| 3-6 字数契约 → **三档**（A 正文／B +文献+表注／C +附录）＋换刊重算 | 旧版只有"含/不含参考文献"一档；换刊时没人重算。现在 A 少 >20% 先判"换刊还是砍发现" |
| 5-4 六缝：补"定义-证据缝""比较单位缝" | 旧版叫六缝、实际只有四行；补两行后名实相符。前者防"定义大于证据"，后者防"平台差异其实是主体构成差异" |
| 新增 6-6 数据-主张对账 | 写完发现后，凡"全量/所有"主张回编码表核覆盖率；不足 100% 改口径 |
| 新增 8-6 三角色审稿（建议） | 理论/方法/目标刊读者各 3 条；只改"成立"的。这次 P0 就是靠这个抓出来的 |
| 9-2 加"字符限制字段" | 标题、running head、推广摘要、tweet 按字符数；系统说 character 就数字符 |
| 9-2 Cover Letter 加"近刊/专题一句" | 这次引了 JTCC 24(4) 专题，比空说"贵刊合适"有效 |
| 9-3 加"投稿包冻结" | 投完才要做"含作者版"；不冻结就会改乱投稿版 |

## 三、刻意不做的

1. **不把九步扩成十二步**：步骤一多，人和 AI 都记不住。新东西都挂到已有步骤下（3-6、5-4、6-6、8-6、9-2、9-3）。
2. **不在正文写"为什么"**：理由只在本文件与 CHANGELOG；SOP 正文只留判据。
3. **不镜像到 `zh/`**：中文线是 8 份独立 SOP，结构与英文线不同；强行同步会制造两套半成品。
4. **不新增 `checks.yaml`**：目前 02 的十四项已是单一清单；再加机器版会形成第二事实源。等脚本化需求明确再加。
