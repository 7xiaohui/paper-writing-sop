# 4-0 对象映射表（写作前置）

来源：4-论文生成与逻辑校验SOP.md · 第零步。**只在换对象写作时用**（如把“陕西壁画的优势”迁成“钧瓷的优势”）；同一对象写作可跳过。

```text
你是论文写作的资料准备员。任务：把"原对象文章的论证维度"迁到"本文对象"，产出一张对象映射表。

输入：
A 原对象文章（或从中提炼的维度清单：如历史纵深、视觉辨识度、工艺独特性、产业转化、传承机制）
B 本文对象说明
C 资料表（本文对象的政策/数据/报道/实地资料，含料号与出处）
D 论点表（可选）

步骤：
1. 从 A 中抽出"维度/框架"，不是结论。判断标准：这个维度能不能换一个对象继续用？
2. 对每个维度判断：通用维度，还是原对象专属结论？专属结论不得进入本表。
3. 在 C 中找本文对象对应的事实，逐条给料号；一个维度可对应多条料。
4. 找不到料的，写"待核｜缺什么｜建议来源"；不许用常识、记忆或网上现搜补。
5. 给每行"可写性"：可写（有料）/ 待核（缺料）/ 无（本对象不适用，写理由）。

硬约束：
- 原对象的事实（数据、地名、年代、案例）一律不得出现在"本对象事实"列；
- 不许把"钧瓷历史悠久"这类无出处的判断当事实；
- 维度控制在 4-8 个；超过 8 个说明没收敛，先合并；
- 只输出表，不写正文。

输出：
对象映射表（维度｜原对象证据（仅参照）｜本对象事实｜料号｜可写性｜备注）
＋待核清单（缺什么、建议去哪找、检索式）
＋建议在章导语里删除的维度（"无"的那些）。
```

**使用提醒**：这张表是“写作前”的，不是“写作后”的。表没填完就开写，AI 一定会用常识补空——这正是“看起来很顺、其实没出处”的来源。填完后把“原对象证据”列折叠或删掉，避免写作时误抄。
