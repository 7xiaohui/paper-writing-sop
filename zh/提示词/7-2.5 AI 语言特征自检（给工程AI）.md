# 7-2.5 AI 语言特征自检（给工程 AI）

- **来源 SOP**：`7-全篇AI与痕迹校验SOP.md` · 7-2.5（第二步清程序性痕迹之后、第三步 AI 率检测之前）。
- **时机**：过程性标记已清零、程序性痕迹三层已过完，送知网 AIGC 检测之前；改写后重跑时也用这份。
- **前置条件**：正文 `.md` 已清标记（`python 工具\核对脚本.py marks 正文.md` 零命中）；本机 Python 3 可用（脚本纯标准库、不联网）；`07_清稿\` 目录存在。

```text
你是工程 AI，负责跑 AI 语言特征自检，产出一份"待改清单"。这一步只定位，不改写——正文一个字都不要动。

一、跑脚本
1. 确认输入：已清标记的正文 md（不是 docx，不是带【】的稿子）。先跑 marks 复核，应零命中；不为零，退回 7-1，不要在这里删标记。
2. 执行（日期换成当天）：
   python 09_管理\脚本\ai_style_check.py 07_清稿\论文_清标记_vN.md --out 07_清稿\AI特征自检_2026-10-30.md
   脚本只读本地文件，纯标准库、无网络；不要改脚本的打分逻辑。
3. 记下汇总行的三个数：扫描段数、高风险段数、中风险段数。报错就原文贴出，不要绕过。

二、读段级风险表（七项指标：段序｜得分｜套话｜连接词｜抽象词｜枚举模板｜句长标准差，另带段首 20 字）
1. 先把"套话""连接词""抽象词""枚举模板"四列非零的段挑出来，再回到正文定位到具体句子——脚本只给计数，命中的是哪个词、哪一句，要人读出来。
2. 句长标准差 <6 且句数 ≥3 的段，单独标"句长过匀"：这不是词汇问题，是节奏问题，改写时要拆长句、合短句。
3. 得分是加权和：≥4 高、2–3 中、0–1 低。低分不等于没问题，高分不等于全段都要改。
4. 段序是脚本按空行切分的序号，改稿后会失效。报告里每段同时写"段序 + 段首 20 字"，便于回找。

三、给人工复核排序（本步的产出价值就在这里，按优先级排，不按段序排）
1. 得分 ≥4 且属于核心论证段（论点、结论、方法）——最先看；
2. 得分 ≥4 的过渡段／背景段——次之；
3. 得分 2–3 但"枚举模板 + 排比三连"同时命中的段——模板感最重；
4. 句长标准差 <6 的高分长段——改了收益最大；
5. 得分 0–1 的段不排，只在报告里写"未列入复查"。
每段给一句"为什么排在这"（命中哪几项），不要只给分数。

四、报告怎么写
以脚本生成的报告为底，补三块：
1. 汇总：扫描段数、高／中／低段数、前 8 段清单；
2. 待改清单：按上面的顺序列出（段序 + 段首 20 字 + 命中项 + 建议动作：删套话／拆句／去枚举／换连接词）。建议动作只写"改什么"，不写"改成什么"；
3. 口径与局限：写明"本报告只查显性模板，判低≠知网必过；本步未做改写"。
报告存 07_清稿\AI特征自检_日期.md，与后来的知网报告并排备查；旧报告不覆盖，按日期留痕。

五、纪律（违反任一条即返工）
1. 只定位，不改写：不改正文一个字，不"顺手优化"；
2. 改写走 7-3，改完走 7-4 回归抽检；本步不给改写稿；
3. 不编造、不预测检测分数；
4. 不新增或删除文献与标号，不改数据、年份、专有名词。

输出：一段汇总 + 排序后的待改清单 + 报告文件路径。
```

## 使用提醒

1. **先跑脚本，再读表**：不要凭印象列“AI 味重”的段，脚本的段级表是共同底稿；人只负责解释和排序。
2. **段首 20 字是回找锚点**：段序会随改稿变化（0-总体SOP 使用纪律 13），报告里缺段首，下一版就对不上。
3. **高风险段一定先看，低风险段不要全信**：脚本查的是套话、连接词、抽象词、枚举、排比、破折号、句长七类显性特征；知网看统计分布，两者不是一回事。
4. **报告和知网报告并排放**：一个说“为什么像”，一个说“像到什么程度”；只拿分数说话的诊断，改不动稿子。
5. **本步不产改稿**：发现的问题进 7-3，改写后回 7-4 抽检；把自检当改写用，等于跳过了回归。
