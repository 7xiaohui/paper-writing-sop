# 7·全篇AI与痕迹校验——标准操作文件

## 本项工作做什么

定稿前最后一道检查：把全文里所有“AI 辅助过程留下的东西”清干净——过程性标记、程序性痕迹、AI 生成特征——并确认改写没有把论文改坏。只清表达与痕迹，不再动逻辑和事实。

本环节的顺序是：清标记 → 清痕迹 → **AI 语言特征自检（7-2.5）** → 测 AI 率 → 改写 → **回归抽检** → 重测 → 查重。第五步是新增的：改写是唯一会“动到字”的操作，动完必须回头验一次。

v5 在第二步与第三步之间插入了 **7-2.5 · AI 语言特征自检**。它是附加检查，不是新的“第几步”：原有第三步到第七步的步序不重排（第三步仍是 AI 率检测，第四步改写，第五步回归抽检），7-3／7-4 的编号也不动——这样提示词文件与 0-总体SOP 里的引用才对得上。

## 你手上有（输入）

- 论文定稿初稿（已通过逻辑校验、命题反方检验和事实校验）；
- 资料表（事实材料索引，降 AI 率改写补细节时用，**也只能用这里的细节**）；
- 目标机构/期刊对 AI 率与查重的具体要求（没有就按最严的公开标准自查）。

## 做完交出去（输出）

- 干净的正式稿：无过程标记、无程序痕迹、AI 率达标、查重达标；
- **改写回归抽检记录**：抽了哪些段、对照了什么、有没有改出原文没有的意思。

## 怎么做

### 第一步 · 清过程性标记

**目标：标记 0 残留。** 不是“删到只剩几个例外”，是全文一处不剩；markdown 源稿与导出的 docx 里都不许有。

要清的两类：

1. **夹注**：【论N】【述】【推】【料N】【待核】【待定】【待补出处】【补：……】等一切括号夹注；
2. **AI 提示语**：写作时 AI 留下的草稿性说明，如“这里需要补充数据”“此处理应引用某文献”“（见资料表料5）”。

**先解决，再清**：【待补出处】【待核】【待定】不是“可以先留着”的标记——它们表示内容还没补齐。删标记之前必须先处理：出处补上、事实核实、表述定下来，把内容写进正文，再删标记。补不了就停下来问，**不许带着标记进 docx**：带进去的标记会被当作正文排版，送检时也解释不清（0-总体SOP 使用纪律 17：送检前占位标记必须清零）。

清法：**先用脚本扫一遍** `python 核对脚本.py marks 终稿.md`，输出全部【…】标记及位置；再逐条删。删完后检查有没有留下断句问题、空行、孤立标点。

脚本扫完必须是**零命中**——肉眼扫一遍就宣布“清干净了”，是这一环最常见的漏。导出 docx 后再另存为 txt／md，用 `marks` 扫一遍，仍为零才算过。

### 第二步 · 清程序性痕迹

1. **标点层——三层都要过，缺一层就返工**：
   - **字符层**：英文直引号 `"` `'`、半角括号与逗号句号 → 换成中文弯引号“”‘’与全角标点。**最容易漏的是这一层**：文稿若由 Markdown 转换而来，直引号会原样搬进 docx，搜“引号”看不出区别，只看字符编码才认得出来；
   - **字形层**：字符换成中文标点之后，还要确认它归哪个字体渲染。run 的 `rFonts` 缺 `w:hint="eastAsia"` 时，Word/WPS 会把引号、破折号、省略号按西文字体排，占位明显偏窄——屏幕上看着像“没改过”，其实字符已经对了。**这一层只能靠脚本或查 XML，肉眼纠不出来**；
   - **间距层**：中文标点前后不加空格；半角标点转全角后若留下空格，一并删掉。

   先用脚本过一遍：`python 核对脚本.py punct 终稿.docx`（`.md` 也能查，但只覆盖字符层与开合，查不到字形层）。它能查哪三层、哪些只能人工补，见下。

   **字形层怎么验（独立方做，不采信导出工具的自检数）**：拆开 docx，在 `word/document.xml` 里数两个数——① `w:hint="eastAsia"` 出现次数；② 含中文的 run 数。两个数都要报：`hint 数 < 含中文 run 数` 即不合格；两数相等也不能直接放过，要确认每个含中文 run 自己带了 hint（hint 可能落在无中文的 run 上）。**导出工具自报的“缺 0”不算数**：实例中导出脚本自检报“缺 0”，独立方实测 111 个含中文 run 全缺。自检数只作线索，必须由独立方在文件上复核（0-总体SOP 使用纪律 14），复核者按使用纪律 6 换会话或换模型族。

   ```python
   # 独立复核：hint 数与含中文 run 数
   import re, zipfile
   xml = zipfile.ZipFile("终稿.docx").read("word/document.xml").decode("utf-8")
   runs = re.findall(r"<w:r[ >].*?</w:r>", xml, re.S)
   cjk = [r for r in runs if re.search(r"[\u4e00-\u9fff]", r)]
   miss = [r for r in cjk if '<w:hint="eastAsia"' not in r]
   print("含中文 run %d ｜ w:hint 出现 %d ｜ 缺 hint %d" %
         (len(cjk), xml.count('<w:hint="eastAsia"'), len(miss)))
   ```

   **`punct` 能查什么、查不到什么**：`python 工具\核对脚本.py punct 终稿.docx` 查三层——**字符层**（ASCII 引号、夹在汉字间的半角标点）、**字形层**（含中文 run 缺 `w:hint` 的数量，及其中含引号／破折号／省略号的 run 数）、**开合层**（“”‘’左右是否等数）；`.md` 只覆盖字符层与开合层。注意：本步要的三层是字符／字形／**间距**，脚本覆盖的是字符／字形／**开合**——**间距层脚本不查**，中文标点前后的空格仍需人工过一遍。

   **盲区（脚本不读，必须人工补查）**：页眉页脚、脚注尾注、文本框、批注、画布（图形、艺术字、图表内文字）。脚本只扫正文段落与表格单元格，这些位置的 ASCII 引号、半角标点、缺 hint 都不会报——页眉里的作者单位、脚注里的基金信息、文本框图注最常中招。**盲区不是“应该没事”，是“脚本没看”**：跑完要逐处打开人工核对，并在交付说明里写明查过哪些位置。

   **修的顺序**：先改源文件（.md 或生成脚本），再重新导出 docx。在 docx 里逐字手改，等于把同一个毛病留在源里，下次重新生成又回来。

2. **渲染层**：Markdown 残留（`**`、`#`、`-`、`|` 表格竖线）、代码块标记、HTML 标签残留；
3. **不可见字符**：零宽空格等特殊字符（用脚本扫描替换）；
4. **文件层（docx）**：文档属性里的作者、最后修改者、应用程序、公司、标题、关键词——清掉 AI 工具名，改成本人信息。用脚本一条命令做：`python 核对脚本.py props 终稿.docx --author 你的名字 --title 论文标题`（可先加 `--dry-run` 看会改哪些字段；Word 里“文件→信息→属性”是备用办法）；
5. **文件层（文件系统）**：`~$` 开头的临时文件、隐藏文件、AI 工具缓存；图片去除 Exif 或重新导出。

**注意**：第四项与 SOP-8 的匿名化是两件事——这里改成本人信息，投稿若是双盲评审，SOP-8 再改成匿名稿，不要在这里就抹掉作者。

### 7-2.5 · AI 语言特征自检

**位置**：插在第二步清程序性痕迹之后、第三步 AI 率检测之前；它是附加检查，不占步序（原因见文首）。

**为什么放在检测之前**：机器检测是黑箱——等报告只能干等，报告也只说“哪段分高”，不说“为什么高”。这一步先用本地脚本把“像机器写的”显性特征找出来，先改一轮再送检，少返工一轮。

**工具**：`09_管理\脚本\ai_style_check.py`。纯本地、只用 Python 标准库、不联网、不上传正文，稿子不出本机。

```powershell
python 09_管理\脚本\ai_style_check.py 07_清稿\论文_清标记_vN.md --out 07_清稿\AI特征自检_2026-10-30.md
```

**输入**：已清完标记的正文 `.md`（第一步之后）。带【】的稿子不能跑——标记会被算进段长和句长，分数失真。**输出**：段级风险表（段序｜得分｜套话｜连接词｜抽象词｜枚举模板｜句长标准差）＋全稿得分前 8 段（无论档位，供人眼复核），另附高／中／低档位汇总。

**查什么（七项）**：

1. **模板套话**：“值得注意的是”“综上所述”“不可忽视的是”“随着……不断发展”“在……的大背景下”“具有重要的现实意义”等；
2. **机械连接词密度**：因此／然而／此外／同时／进而／首先／其次／最后等成串出现；
3. **抽象名词堆叠**：机制／路径／维度／体系／赋能／协同／范式／场域等，一句里摞三个以上；
4. **枚举模板**：“第一……第二……第三……”整段按模板铺开；
5. **排比三连**：三个短句同构并列，且连续出现；
6. **破折号滥用**：一段里两个以上“——”；
7. **句长标准差过小**：句子长短过于均匀，是机器文本最典型的结构特征（脚本对 ≥3 句且标准差 <6 的段直接加分）。

**阈值**：得分 ≥4 高风险、2–3 中风险、0–1 低风险。**阈值只是提示，不是判决**：高分段一定先看，低分不代表没问题——脚本查的是显性模板，检测工具看的是统计分布。

**纪律（三条）**：

- **只定位，不改写**：这一步产出“待改清单”，不产出改后的稿子；脚本和人都不在这里动字；
- **改写仍走 7-3**：按 7-3 的原则改（只改表达，不改观点、数据、引文编号，不新增论断），改完照旧做 7-4 回归抽检；
- **判低不等于知网必过**：脚本没命中只说明“没有明显模板腔”，不构成检测结论；送检分数才是结论，且同样是提示不是判决。

**报告存档**：`07_清稿\AI特征自检_日期.md`（如 `AI特征自检_2026-10-30.md`），与知网 AIGC 报告并排备查；改稿后重跑，旧报告不覆盖，按日期留痕。

本步提示词见 `提示词\7-2.5 AI 语言特征自检（给工程AI）.md`。

### 第三步 · AI 率检测

- 用检测工具（知网 AIGC 检测或其他学校/期刊认可的工具）跑全文；
- 输出：高 AI 概率段落清单；
- 注意：结果是提示，不是判决，误报很常见（尤其是规范的政策表述、方法步骤）。

**没有可用检测渠道时**：不要编造分数，改为“套话自查 + 人工抽读”——按第四步的套话清单逐条搜（值得注意的是/综上所述/不可忽视的是/在当今时代背景下/不仅…而且…/一方面…另一方面），把命中处列成清单，再抽读 10 段判断是否机械。并在交付说明里写明“未做机器检测”。

### 第四步 · 降 AI 率改写（人机协作，人拍板）

改写原则：

1. **句长打散**：长句拆短、短句合长，让句长有起落（AI 生成句长最均匀）；
2. **删换套话**：“值得注意的是”“综上所述”“不可忽视的是”“在当今时代背景下”等 AI 高频词，删或换；
3. **句式变化**：主动/被动、状语位置、因果表述换着用，避免“不仅…而且…”“一方面…另一方面…”连续出现；
4. **段落节奏**：段落长度错落，避免整篇段落等长；
5. **具体化（有条件）**：能补真实机构名、年份、数据的地方补上——**必须来自资料表，且不得因此新增论断**。补一个数字就多一条主张，这条主张也得有锚点。

**硬约束**（防止改写改坏）：

- 只改表达，不改观点、数据、引文编号；
- **不新增任何论断**，包括“顺带一提”式的补充；
- **不整段重写**：按句/按段小步改，改完能逐句对照原文；
- 拿不准的保留原文并标出，交人判断。

### 第五步 · 改写后回归抽检（新增）

改写是唯一会改变字面的操作，必须在改完之后回头验一次，不能直接进入查重。

**抽检方法**：

1. 每章抽 1-2 段，总量不少于全文的 10%（至少 5 段），优先抽改写幅度大的段落；
2. 每段对照三样东西：原文（改写前）、论点表、资料表；
3. 逐项检查：
   - 有没有新增原文没有的主张或判断？
   - 数字、年份、比例、机构名有没有被改动？
   - 引文编号有没有错位或丢失？
   - 关键术语有没有换成近义词导致前后不一致？
4. 记录进《修改台账》的“改写”分区：段落位置 / 改写类型 / 抽检结论 / 是否回退。

**不通过的处理**：该段回退到改写前版本，换一种改法（或保留原样、只在检测报告里说明）。**不允许“抽检发现问题但算了”**——这是全流程最后一处可能悄悄引入错误的地方。

### 第六步 · 重测迭代

改写后重跑 AI 率检测，直到达标（按目标期刊/学校的具体要求，不设固定值）；未达标的段落继续改，循环。第二轮及以后的改写，仍要抽检新改的段落。

### 第七步 · 查重

- 用知网等查重系统跑最终稿；
- 重复率超标段落人工改写——不能整段删除（伤结构），不能改变论点。
- **总文字复制比偏低（<5%）且他引记录少**：别当成“原创性好”就收工——查重低而 AI 率高，正是机器文本的典型特征。回头补 4–6 处原文直引，优先复引已经在参考文献表里的文献（不新增文献、不新占号），逐字照录、加 [n]；补完重跑 6-2 标号校验。**不在盲检前硬凑**——为凑比例而引，正文与文献没有真实接触，反而更露。直引比例口径见 0-总体SOP 编号接口（1%–5%）。

## 通过标准

- 全文（含导出 docx）无过程性标记（脚本零命中）、无程序性痕迹；
- **标点三层零遗留**：`punct` 零命中——0 个 ASCII 引号、0 处汉字间半角标点、含中文的 run 100% 带 `eastAsia` hint；引号开合数相等；页眉页脚／脚注／文本框／批注／画布等盲区已人工补查；
- docx 属性已改成本人信息，无 AI 工具名残留；
- AI 率达标（按目标期刊/学校要求），或已明确记录“未做机器检测”及自查结果；
- **回归抽检已做、记录在案、无未处理的不通过项**；
- 查重达标（按目标期刊/学校要求）；
- 所有改写未改变论点、未破坏事实（抽读对照）。

## 注意事项

- 本环节是最后一道，改完不再动逻辑和事实；发现硬伤回到对应环节修；
- 检测结果是提示不是判决：误报存在，以人判断为准；
- **禁止用“一键降AI率”工具批量重写**——新生成会带新的生成痕迹，还可能语义漂移；
- 补细节必须对照资料表，不许引入资料表外的数据；
- **伦理边界**：本环节的目的是让表述更像本人写作、更少机器腔，不是伪造“从未使用 AI”的事实。若目标机构要求申报 AI 使用情况，按实际情况申报，不要用检测结果去对抗学术规范；
- **标点必须看渲染，不能只看字符**：把“”换成中文引号只是第一步，字体归属不对，屏幕上依旧是西文占位。改完在 Word/WPS 里放大到 200% 看一眼，或直接跑 `punct` 查 run 属性；
- 不要在这一步改标题、结论、核心命题——那属于 SOP-4/8。

## 提示词

### 提示词1 · 清过程性标记（给整理 AI）

```
请扫描论文全文，找出并列出所有过程性标记：
1. 夹注类：【论N】【推】【料N】【待核】【待定】【待补出处】【补：……】等括号夹注；
2. 提示语类："此处需补充数据""应引用某文献""（见资料表料5）"等草稿性说明。
输出：标记清单（位置/内容/类别），逐条给处理建议（删/留问人）。
然后按处理结果删除；删完后检查断句、空行、孤立标点，列残留问题。
最后再全文扫一遍，确认【】类标记为 0 处；若有残留，逐条列出。
```

### 提示词2 · 清符号与渲染残留（给整理 AI）

```
请处理论文全文的程序性痕迹。标点部分分三层，逐层报告，不要合并成一句"已统一"：

第一层·字符：英文直引号 " '、半角括号、半角逗号句号 → 换成中文弯引号“”‘’与全角标点。
  注意：从 Markdown 转来的文稿，直引号会原样保留；请按字符逐一统计，给出 ASCII 引号的数量与位置。

第二层·字形（仅 docx）：检查每一处引号、破折号、省略号所在的 run 是否带 w:hint="eastAsia"。
  缺这条属性的 run，中文标点会按西文字体渲染，占位偏窄。请报告：含中文的 run 总数、缺 hint 的数量、其中含标点的数量。

第三层·间距：中文标点前后是否有空格；半角转全角后是否留下空格。

另处理：
1. 渲染残留：Markdown 符号（**、#、-、|）、代码块标记、HTML 标签 → 清除；
2. 不可见字符：零宽空格等 → 清除。

输出：三层的统计与位置清单（字符编码层面的判断，不要凭"看起来一样"下结论），以及需要人工确认的项。
不要改动数字、引文标号、专有名词的中英文混排。
```

### 提示词3 · 降 AI 率改写（给人机协作改写）

```
请对以下段落做"去 AI 味"改写。只改表达，不改观点、数据和引文。

改写原则：
1. 句长打散：长句拆短、短句合长，避免整段句长均匀；
2. 删除或替换 AI 高频套话："值得注意的是""综上所述""不可忽视的是""在当今时代"等；
3. 语序与句式变化：主动/被动、状语位置、因果表述换着用；
4. 段落节奏：句子长短错落，避免"不仅…而且…""一方面…另一方面…"连续出现；
5. 具体化只在有材料时做：只能用我给的资料表里的信息，且不得因此新增论断。

硬约束：
- 不新增任何论断，不补充资料表以外的机构名、年份、数据；
- 不整段重写，按句/按段小步改；
- 不改动任何论点、数据、引文编号；术语保持前后一致；
- 拿不准的地方保留原文并标出。

输出：改写后的段落；如有改动数字、术语、引文，单独列出改动清单。
```

### 提示词4 · 改写后回归抽检（给复核 AI）

```
你是一名校对员，任务是判断改写后的段落有没有"改出原文没有的意思"。

你手上有：改写前的原文、改写后的段落、论点表（可选）、资料表（可选）。

逐段核对四项：
1. 新增主张：改写后有没有出现原文没有的判断、因果、评价？有则指出句子。
2. 数字与专名：年份、比例、数量、机构名、政策文号有没有被改动？
3. 引文编号：有没有错位、丢失、重复？
4. 术语漂移：关键概念有没有被换成近义词，导致与全文用法不一致？

输出：逐段清单（段落位置/结论：通过或问题类型/问题句对照/建议：保留改写或回退）。
不要评价文笔好坏，只判断"意思有没有变"。
```
