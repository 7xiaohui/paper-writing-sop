# 中文论文写作 SOP · AI 辅助流水线

把「选题 → 文献 → 资料 → 成稿 → 校验 → 痕迹清理 → 投稿」拆成 8 份可单独执行的标准操作文件。每份都写清三件事：**输入从哪来、输出往哪去、什么样算通过**，并附可直接粘贴的提示词。

写给非实证论文（政策对策、描述分析、理论构建类），以论证性命题为主线，不做统计推断。

> 本目录是 [`paper-writing-sop`](../README.md) 的中文线，可单独使用：在 `zh/` 下工作时，文中命令直接可用；在仓库根目录运行时，命令路径前加 `zh/`。

---

## 为什么不是「直接让 AI 写」

AI 写论文的通病不在于不会写，而在于四类可复现的失败：**编造**（数据、文献、条款）、**跑题**（论证与主题脱节）、**型错**（把描述段当论证段）、**留痕**（标记、直引号、文档属性里的工具名）。

这套文件的做法是把这四类失败逐条变成检查项和验收标准：能脚本查的不靠肉眼，能指到文件的结论不靠感觉，复核者与写作者不共享上下文。

## 核心设计

**1. 自包含，可跳跃**
每份 SOP 都能单独交给一个不了解前情的 AI 执行；从任意一环进入，按该环的「输入」清单补齐前置产物即可。

**2. 脚本优先于模型**
字符串比对、数字比对、引文标号映射、文档属性清理、标点与字形检查，先跑 [`工具/核对脚本.py`](工具/核对脚本.py)：

```bash
python 工具/核对脚本.py refs    正文.md 参考文献.txt   # 引文标号双向映射
python 工具/核对脚本.py numbers 正文.md 资料表.md       # 数字与底表比对
python 工具/核对脚本.py mats    正文.md                # 【料N】抽取计数
python 工具/核对脚本.py marks   正文.md                # 过程标记扫描
python 工具/核对脚本.py punct   论文.docx              # 标点三层：字符/字形/开合
python 工具/核对脚本.py props   论文.docx --dry-run    # 文档属性查看与清理
```

退出码：0 未发现问题，1 发现问题，2 参数或环境错误。模型负责判断，脚本负责「有没有」。

**3. 复核必须独立**
4-2、5-2、6-3、7-4 的复核者不得与写作者共享上下文——换模型、换会话，或把材料无状态重投一次。

**4. 标记即欠账**
【待核】【待定】【待补出处】【料N】等临时标记在生成期有用、投稿期有害，全部在 SOP-7 清零，且要脚本零命中才算完。

## 一个例子：标点为什么单列一层

中文稿里的引号有三层问题：**字符**（ASCII `"` 而非 `“”`）、**字形**（run 缺 `w:hint="eastAsia"`，中文标点被按西文字体排，占位偏窄）、**开合**（左右不等）。第二层文本搜索搜不出来、肉眼也难判断，只有查 XML 或量占位宽度才认得出，所以它被写成独立的检查项，而不是「顺手改一下标点」。

## 使用

- 从 [`0-总体SOP.md`](0-总体SOP.md) 读起，先看「八份一览」与「单独执行与跳跃执行」两节；
- 只想解决一个问题时，直接取对应那一份，不必跑全流程；
- 提示词可直接粘贴给任意模型，替换方括号里的占位信息即可；
- 换题材时先看 [`示例-陕西壁画迁移到钧瓷.md`](示例-陕西壁画迁移到钧瓷.md)：能搬的只有维度，搬不动结论和证据。
