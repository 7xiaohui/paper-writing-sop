# 工具：五个检查脚本

> 你不需要看懂代码。只做三件事：**放稿 → 双击 → 看报告**。
> Windows 用户双击 `.bat`；macOS / Linux 用户直接跑 `python scripts/check_*.py input output`（脚本只用标准库）。

---

## 一、第一次用（5 分钟）

1. **装 Python**：到 python.org 下载 3.x，安装时**勾上 "Add Python to PATH"**。
2. 双击 `run_all.bat`。
3. 如果控制台出现"找不到 python"，说明没装好或没勾 PATH，重装一遍。

> 第一次用投稿件生成器之前，先把 `docx_config.example.txt` 复制一份、改名为 `docx_config.txt`，再填自己的作者信息（见第五节）。

---

## 二、日常用法

```
① 把稿件放进 input/
   （支持 .docx / .md / .txt，可以放多份，会逐份出报告）
② 双击 run_all.bat
③ 打开 output/ 里的五份报告
④ 按报告改稿，改完重跑
```

**注意**：脚本只读、不改稿。每次运行还会写 `output/run_log.txt`——**窗口一闪就没了的时候，打开它看原因**。

## 三、五个脚本查什么

| 脚本 | 查什么 | 输出 |
|---|---|---|
| `check_counts.py` | 摘要词数、关键词数、正文词数、中文字符数 | 是否超目标刊上限 |
| `check_terms.py` | 禁用写法、美式拼写、术语出现次数 | 命中行号 + 原文 |
| `check_refs.py` | 文献表里未在正文出现、正文引了表里没有、缺 DOI、疑似重复 | 候选清单（需人工确认） |
| `check_consistency.py` | 摘要↔正文↔结论的发现项数、人称混用、双结论、引用编号与标题编号是否对得上 | 差异表 |
| `check_clean.py` | 六类工作痕迹、占位符、整段加粗、假脚注、刊名残留 | 命中行号 + 原文 |

**`check_refs.py` 用保守判法**：文献表里该作者名在正文中一次都没出现，才列为"疑似未引用"（`et al.`、`Smith's` 都算出现）。所以它宁可漏报，不制造假阳性；列出来的值得逐条核。

**`check_consistency.py` 的两个注意**：
- "发现项数"只认明确的表述（如 four findings / reports five findings），不会把 "5.1 Finding One" 这类小节号算进去；
- 人称：`we/our` 出现 2 次以上且同时用 this study/paper 才算 FAIL；只出现 1 次 `we` 判 WARN（可能是修辞用法），你自己决定改不改。

**参数**：改 `config.txt`（正文上限、摘要上限、关键词个数、不许出现的刊名）。不用改代码。

## 三·补、生成投稿件（build_docx）

```
① 把 md 源稿放进 input/
② 双击 生成投稿件.bat
③ output/docx/ 里会出四份：
   匿名主稿 / 标题页 / CoverLetter / 图注表
```

**它自动做三件事**：按 `docx_config.txt` 替换作者信息（匿名稿里变成 `[Author]`）、移除致谢段、清掉文档属性（缩略图、生成器名、修订痕迹）。


**限制（重要）**：
- **只处理 `.md / .txt`**。docx 不参与重建——docx 里的表格合并、页眉页脚、编号样式无法保真还原，硬转会失真；
- 表格是基础样式，合并单元格会退化，生成后在 Word 里调一次即可；
- 首次使用若提示 `ModuleNotFoundError`，双击 `安装依赖.bat`（装 python-docx，只需一次）。

**`docx_config.txt` 填什么**：标题、作者、机构（**官方英文名**）、邮箱、ORCID、基金号、目标刊、主编、致谢。留空的行不会出现。`anonymize=1` 表示生成匿名稿。

> **先复制再填**：把 `docx_config.example.txt` 复制为 `docx_config.txt`，再改内容。`docx_config.txt` 含作者个人信息，已被 `.gitignore` 排除；**不要把它提交到公开仓库**。

## 四、术语表怎么维护

`terminology.csv` 五列：

```
中文,英文,类型,禁用写法,允许次数
解释密度,explanation density,核心概念,解释密度值|explanation quantity,0
政策空转,policy inaction,弃用,policy vacuum|政策空转,2
```

- **中文/英文**：你的定译；
- **类型**：核心概念 / 概念 / 弃用；
- **禁用写法**：多个用 `|` 隔开；正文出现就报；
- **允许次数**：正文里最多允许出现几次。**"受限允许"用这一列**（例如某个弃用概念，你在概念取舍处必须交代 2 次，就填 2，超过才报错）；
- 文献表（References 之后）里的命中**不计入失败**——他人标题原文必须保留，报告里单列提示。

**加词不用改代码**，只加一行。用 Excel 编辑后**另存为 CSV（UTF-8）**。

## 五、怎么确认脚本没坏（正负样本自测）

**一条命令**（在仓库根目录）：

```bash
python tests/verify.py
```

它会自动把 `samples/good.md`、`samples/bad.md` 分别喂给五个脚本，断言 good 全过、bad 至少 5 项失败。输出结尾是 `==== 全部通过 ====` 就说明脚本没坏。

**手动跑**（想亲眼看报告时）：

```
① 把 samples/good.md 复制进 input/ → 跑 → 应全部 PASS
② 把 samples/bad.md  复制进 input/ → 跑 → 应至少 5 项 FAIL
   （摘要超长、关键词不足、禁用词、美式拼写、未引用文献、缺 DOI、
     发现项数不一致、人称混用、整行加粗、版本号残留）
③ 如果 bad.md 也 PASS → 脚本坏了，开 Issue 附上 output/ 里的报告
```

> 这是你不懂代码也能验收的办法：**看它会不会抓错**。
> 像用冰水试体温计——不会修，但能验证。

## 六、报告长什么样

`output/report_counts_good.md`：

```
| 检查 | 结果 | 详情 |
| 摘要词数 <= 200 | PASS | 实际 108 词 |
| 关键词 3–6 个 | PASS | 实际 5 个 |
| 正文词数 <= 8400 | PASS | 实际 365 词 |
**PASS 3/3**
```

最后一行一定是 `PASS n/n` 或 `FAIL n/n`。**看这一行就够了。**

## 七、常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| **双击闪退** | 旧版 bat 是 LF 换行（已修）；或 Python 未装 | 先看 `output/run_log.txt`；没有这个文件说明 bat 没跑起来，重下本目录的 bat |
| 控制台中文乱码 | 终端编码 | 报告文件本身是对的，直接打开 output/ 里的 .md |
| 找不到 python | 未勾 PATH | 重装 Python，勾 "Add Python to PATH" |
| 报告说找不到稿件 | input 为空，或只放了 README | 把 .docx / .md 放进 input/ |
| 读 docx 没反应 | 文件被 Word 占用 | 先关掉 Word 再跑 |
| 摘要词数明显不对 | 稿里没有单独的 `Abstract` 行 | 让 "Abstract" 单独占一行 |
| 关键词数 = 0 | 没有 `Keywords:` 行 | 写成 `Keywords: a; b; c` |
| 参考文献条目数不对 | 标题不是 `References` | 用 `References` 单独一行 |
| "疑似未引用"很多 | 正文确实没引到（常发生在压缩版） | 逐条搜姓氏；搜不到就删或补引 |
| 美式拼写误报 | 出现在他人标题/引文里 | 正常，人工放行 |

## 八、以后要加检查项，怎么提需求

照这个格式发我，我出脚本 + 正负样本：

```
【要检查什么】一句话
【输入是什么】文件路径 + 格式
【输出想要什么】表 / 清单
【什么算通过】判据
【举一个错误例子】
【什么时候跑】
```

例：

```
【要检查什么】摘要里说的发现数，和正文、结论是否一致
【输入】input/manuscript.md
【输出】一个表：摘要说几项｜正文说几项｜结论说几项
【通过】三处一致
【错误例子】摘要 "four findings"，正文 "five findings"
【什么时候跑】每次改完摘要
```
